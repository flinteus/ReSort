# Контракт распознавания и рекомендаций

ИИ определяет предмет и материал. Подготовка к сдаче, ограничения и сведения о вреде берутся только из редакционного справочника PostgreSQL. Бэкенд не генерирует их и не принимает такие инструкции в ответе ИИ.

## Передача результата

`POST /api/v1/sorting/recommendation`, заголовок `Authorization: Bearer <access_token>`:

```json
{
  "recognition": {
    "item_name": "Бутылка",
    "category_code": "plastic",
    "material_code": "pet",
    "needs_clarification": false,
    "clarification_question": null
  },
  "region_code": "general"
}
```

Это контракт приёма готового результата модели, а не загрузка фотографии или вызов внешнего ИИ. Результат может передать авторизованный клиент после получения ответа модели. Он не считается доказательством сдачи отходов и не начисляет достижения. Внешнего callback с отдельной сервисной авторизацией пока нет.

`item_name` — 1–200 символов. Коды — строчные латинские буквы, цифры и `_`, начинаются с буквы, до 50 символов. `needs_clarification` обязателен и принимает только JSON boolean. Лишние поля отклоняются с `422`.

ИИ-инженеру следует использовать коды материалов и категорий из `GET /api/v1/waste/materials?region_code=general` (тоже с Bearer-токеном). Этот список содержит только материалы, для которых подготовлены правила в выбранном регионе. Не следует угадывать невидимую маркировку.

## Ответы

- `ready`: возвращены `recognition` и `guidance` из справочника.
- `needs_clarification`: материал не определён либо ИИ запросил уточнение; `guidance: null`, в `clarification_question` — вопрос пользователю. При `needs_clarification: true` вопрос обязателен. После уточнения отправляется новый полный запрос.
- `rules_not_available`: нет правил для материала и указанного региона; `guidance: null`. Не подменяйте этот ответ рекомендациями модели.

Все три состояния возвращают HTTP `200`. Отсутствие авторизации — `401`; невалидный JSON-контракт или несовпадение категории материала со справочником — `422`.

В `guidance` входят:

| Поле | Значение |
| --- | --- |
| `material_code`, `material_name`, `category_code` | Материал и категория |
| `region_code` | Область применимости |
| `preparation_steps` | Массив шагов подготовки |
| `restrictions` | Ограничения и исключения |
| `environmental_impact` | Проверенное описание влияния на природу |
| `sources` | Массив источников `{title, url}` |
| `reviewed_at` | Дата редакционной проверки |

Регион по умолчанию — `general`: это общие рекомендации, а не подтверждение приёма конкретным пунктом. Для другого региона выбирается только точное совпадение; автоматического перехода к общим правилам нет. Конкретные пункты приёма пока не подключены.

## Наполнение справочника

Миграция `0003` создаёт таблицу справочника. Затем Compose импортирует 13 проверенных общих записей из `catalog/waste-guidance.json`, сохраняя существующие записи. Источники и область применимости описаны в [waste-catalog.md](waste-catalog.md). Для отсутствующего материала или региона API возвращает `rules_not_available`.

Модуль `app.cli.import_guidance` принимает путь к UTF-8 JSON-файлу с массивом записей. Формат записи описан схемой `GuidanceImport` в `app/schemas/sorting.py`:

- коды материала, категории и региона, название материала;
- непустой массив `preparation_steps`;
- массив `restrictions` (может быть пустым);
- непустое `environmental_impact`;
- хотя бы один источник `{title, url}`;
- имя проверившего редактора `reviewed_by` и дата `reviewed_at` в формате `YYYY-MM-DD`, не в будущем.

Импорт предназначен для доверенного оператора с доступом к БД; публичной ручки редактирования нет. Записи обновляются по паре `(material_code, region_code)`, повторный импорт не создаёт дубликатов. Весь файл валидируется до записи и импортируется одной транзакцией. Дубли ключей внутри файла отклоняются. Удаление отсутствующих в файле записей не производится.

Наличие URL и имени редактора — метаданные проверки, а не автоматическая проверка достоверности: редактор должен действительно сверить рекомендации с источниками и областью их применимости. API не загружает ссылки источников. Необходимо отдельно актуализировать записи при изменении правил.

Распознавания сейчас обрабатываются без сохранения истории. Тесты используют искусственные записи и откатывают их после проверки; они не наполняют рабочий справочник.
