# Подтверждение сортировки, достижения и дерево

Сортировка — отдельное действие пользователя после подготовки и сдачи отходов. Загрузка фото и распознавание не начисляют прогресс. Реализация не зависит от OpenAI: пользователь может выбрать материал вручную из справочника.

## Подтверждение

`POST /api/v1/sorting-events` требует Bearer-авторизацию и заголовок `Idempotency-Key` с UUID, созданным фронтендом для одного действия. При повторе того же действия используйте тот же ключ и то же тело.

```json
{
  "photo_id": "8ec0f9f9-8b14-4cfa-9bf5-5fdc659d08a1",
  "material_code": "pet",
  "region_code": "general",
  "collection_point_id": null,
  "confirmed": true
}
```

- Фото должно существовать и принадлежать пользователю.
- Материал и регион должны присутствовать в справочнике.
- `confirmed` обязателен и принимает только JSON boolean `true`: строки и числа отклоняются.
- Пункт необязателен: например, сортировка может выполняться в домашний компост или вне каталога. Если пункт указан, он должен быть активным и принимать выбранную пару материала и региона.
- Клиент не задаёт дату подтверждения, количество баллов, уровень дерева или достижения.

Первый запрос возвращает `201`, повтор с тем же ключом и телом — `200`. Ответ содержит:

```json
{
  "event": {
    "id": "80d57387-7bd8-4598-b6d4-2cb5080b84ef",
    "photo_id": "8ec0f9f9-8b14-4cfa-9bf5-5fdc659d08a1",
    "material_code": "pet",
    "region_code": "general",
    "material_name": "Пластик PET / ПЭТ",
    "category_code": "plastic",
    "collection_point_id": null,
    "collection_point_name": null,
    "created_at": "2026-11-08T12:00:00Z"
  },
  "awarded_achievements": [
    {
      "code": "first_sort",
      "name": "Первый шаг",
      "description": "Подтвердить первую сортировку",
      "metric": "sorting_count",
      "target": 1,
      "earned_at": "2026-11-08T12:00:00Z"
    }
  ],
  "tree": {
    "stage": "sprout",
    "stage_name": "Росток",
    "level": 1,
    "sorting_count": 1,
    "distinct_materials": 1,
    "unlocked_achievements": 1,
    "next_stage_at": 3,
    "progress_current": 0,
    "progress_required": 2,
    "progress_percent": 0
  }
}
```

`awarded_achievements` — награды, связанные с этим событием. При повторе запроса возвращаются те же награды, но они не начисляются заново: фронтенду не следует повторно запускать уведомление при `200`. `tree` отражает текущий прогресс и может измениться после других подтверждений пользователя.

Повторное использование ключа с другим телом — `409`. Попытка зачесть то же фото с новым ключом — `409`. Одно фото соответствует одному случаю сортировки, без начисления дополнительных очков за заявленное количество предметов. Повторная загрузка того же изображения под новым ID сейчас не распознаётся как дубликат; это не система доказательства фактической сдачи отходов.

## История

- `GET /api/v1/sorting-events?limit=20&offset=0` — личная история `{items, total}`, от новых к старым. Максимум 100 элементов за запрос, offset до 10000.
- `GET /api/v1/sorting-events/{id}` — личное событие. Чужой или несуществующий ID возвращает `404`.

События неизменяемы через API: ручек редактирования и удаления подтверждений пока нет. Название материала, категория и название пункта сохраняются снимком на момент подтверждения.

При удалении фотографии `photo_id` становится `null`, а история, награды и прогресс сохраняются. Защита от повторного зачёта исходного фото и повтор ключа продолжают работать. Удаление пункта из БД обнуляет его ID в истории, сохраняя название. Удаление пользователя из БД каскадно удаляет его события и награды.

## Достижения

`GET /api/v1/achievements` — публичный каталог условий; `GET /api/v1/users/me/achievements` — полученные награды с `earned_at`, требуется Bearer-токен.

| Код | Условие |
| --- | --- |
| `first_sort` | 1 подтверждённая сортировка |
| `sorting_5` | 5 подтверждённых сортировок |
| `sorting_10` | 10 подтверждённых сортировок |
| `materials_3` | 3 разных `material_code` в подтверждениях |

Достижение выдаётся один раз на пользователя. Разные регионы одного материала не увеличивают число разных материалов. Одно подтверждение может открыть несколько достижений. Каждое событие растит счётчик сортировок, а достижения выдаются при достижении порогов.

## Дерево

`GET /api/v1/users/me/tree` — текущая стадия и прогресс, требуется Bearer-токен. Бэкенд возвращает данные, изображения и анимацию реализует фронтенд.

| Сортировок | Код стадии | Уровень |
| --- | --- | --- |
| 0 | `seed` | 0 |
| 1–2 | `sprout` | 1 |
| 3–5 | `sapling` | 2 |
| 6–10 | `young_tree` | 3 |
| 11 и больше | `mature_tree` | 4 |

`progress_current` — число подтверждений после входа в текущую стадию; `progress_required` — сколько нужно для перехода из неё. `progress_percent` — целое число 0–100. На последней стадии `next_stage_at` и `progress_required` равны `null`, процент равен 100; счётчик сортировок продолжает расти.

Дерево виртуальное: система не заявляет посадку настоящего дерева, массу переработанного мусора или рассчитанную экономию CO₂.

## Согласованность и ошибки

Запись события и начисление всех новых наград выполняются в одной транзакции PostgreSQL. Блокировка пользователя сериализует подтверждения; уникальные ограничения БД защищают ключ идемпотентности, повтор фото и повтор награды. Прогресс дерева вычисляется по сохранённым событиям, отдельного расходящегося счётчика нет.

- `401`: нет действующей сессии.
- `404`: фото чужое/не существует, пункт неактивен/не существует, событие не принадлежит пользователю.
- `409`: конфликт ключа или повторный зачёт фото.
- `422`: отсутствует/неверен ключ, нет явного подтверждения, неверные поля, материал или условия пункта.

Миграция `0006_sorting_progress` создаёт таблицы событий и достижений и четыре определения наград. Она зависит только от `0005_collection_points`, не от локальной ветки миграций OpenAI.
