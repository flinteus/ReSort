# Загрузка фотографий

Все ручки требуют `Authorization: Bearer <access_token>`. Фотографии приватны: файлы не раздаются через StaticFiles и не имеют публичных URL.

## Загрузка

`POST /api/v1/photos` принимает `multipart/form-data` с одним файловым полем `file`. Не задавайте `Content-Type` вручную при использовании браузерного `FormData`: браузер сам добавляет multipart boundary.

```javascript
const form = new FormData();
form.append("file", selectedFile);
const response = await fetch("/api/v1/photos", {
  method: "POST",
  headers: { Authorization: `Bearer ${accessToken}` },
  body: form,
});
const photo = await response.json();
```

Успешный ответ — `201`:

```json
{
  "id": "8ec0f9f9-8b14-4cfa-9bf5-5fdc659d08a1",
  "width": 1600,
  "height": 1200,
  "size_bytes": 150000,
  "created_at": "2026-11-08T12:00:00Z"
}
```

Ответ содержит параметры сохранённого изображения. Исходное имя файла, путь хранения и пользовательские метаданные не сохраняются.

### Проверки и преобразования

- JPEG, PNG и WebP определяются по содержимому, а не расширению или MIME-типу клиента. GIF, SVG, другие форматы и анимация отклоняются.
- Исходный файл — до 10 МиБ, до 20 миллионов пикселей, каждая сторона — до 8192 пикселей. Проверяются заголовок и полное декодирование.
- Размер всего запроса ограничен размером файла плюс 64 КиБ для multipart. Лимит применяется и к потоковым запросам без `Content-Length`; файлы multipart временно буферизуются с этим пределом.
- Ориентация EXIF применяется к пикселям, затем изображение уменьшается с сохранением пропорций до 2048×2048, без увеличения маленьких фото.
- Создаётся новый JPEG с качеством 85 без EXIF/GPS, исходного ICC-профиля, комментариев и приписанного к исходному файлу содержимого. Прозрачность заменяется белым фоном. Видимые на самом фото личные данные не удаляются.
- На диске используются случайные UUID-имена, файлы создаются с правами `0600`. Клиентское имя файла не используется в путях.
- По умолчанию пользователь может хранить 100 фотографий. Проверка квоты сериализована блокировкой строки пользователя в БД. Одновременно декодируются максимум два изображения на процесс API.

## Получение и удаление

| Метод и путь | Результат |
| --- | --- |
| `GET /api/v1/photos/{id}` | Метаданные фотографии |
| `GET /api/v1/photos/{id}/content` | Очищенный JPEG |
| `DELETE /api/v1/photos/{id}` | Удаление файла и записи, `204` |

Контент возвращается с `Cache-Control: private, no-store` и `X-Content-Type-Options: nosniff`. Для показа фото во фронтенде запросите контент с Bearer-заголовком и создайте Blob URL; после использования освободите его через `URL.revokeObjectURL`.

Чужая и несуществующая фотография дают одинаковый `404`. Повторное удаление — `404`.

## Ошибки

| Код | Причина |
| --- | --- |
| `400` | Повреждённая multipart-структура, дополнительные файлы или текстовые поля |
| `401` | Нет действующей авторизации |
| `404` | Фотография не найдена у текущего пользователя |
| `409` | Исчерпана квота фотографий |
| `413` | Превышен размер файла, всего запроса или изображения |
| `415` | Пустой, повреждённый, анимированный или неподдерживаемый файл; неверный Content-Type запроса |
| `422` | Нет единственного файлового поля `file` или неверный UUID |
| `503` | Файл временно недоступен при чтении или удалении |

## Хранение и границы реализации

Миграция `0004` создаёт таблицу метаданных `photos`. Файлы находятся в закрытом локальном каталоге `PHOTO_STORAGE_DIR` (по умолчанию `data/photos`). В Docker Compose этот каталог сохраняется в отдельном volume `photo_data`. Каталог исключён из Git и контекста сборки. Для нескольких серверов потребуется общее приватное хранилище; оно пока не подключено.

Лимиты настраиваются через `MAX_PHOTO_BYTES`, `MAX_PHOTO_PIXELS`, `MAX_PHOTOS_PER_USER`. Верхние границы байтов и пикселей ограничены конфигурацией приложения. Фото сохраняются до удаления владельцем; автоматическая очистка по сроку пока не реализована.

Файл создаётся до коммита записи, при обычной ошибке записи/коммита он удаляется. БД и файловая система не образуют единую транзакцию: аварийное завершение процесса может оставить файл без записи, а ошибка коммита удаления — запись без файла. Для эксплуатации нужны резервные копии и периодическая сверка хранилища с БД. При удалении пользователей напрямую из БД файлы автоматически не удаляются.

Загрузка не запускает модель, не создаёт результат распознавания и не начисляет достижения. Передача фото ИИ-сервису — отдельная интеграция. Текущий контракт распознавания описан в [sorting-api.md](sorting-api.md).
