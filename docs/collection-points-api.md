# Пункты приёма

Реализованы публичные ручки чтения. Для просмотра карты не нужен аккаунт или ключ внешнего картографического сервиса; саму карту отображает фронтенд.

## Поиск

`GET /api/v1/collection-points`

| Параметр | Значение |
| --- | --- |
| `lat`, `lon` | Широта −90…90 и долгота −180…180, обязательно вместе |
| `radius_m` | Радиус в метрах: 1…100000, по умолчанию 5000; применяется только с координатами |
| `material_code` | Код принимаемого материала из справочника |
| `category_code` | Категория материала, например `plastic` |
| `region_code` | Область применимости записи справочника, например `general`; это не город точки |
| `city` | Точное название города без учёта регистра; пробелы по краям удаляются |
| `limit`, `offset` | Пагинация: по умолчанию 20 и 0; максимум 100 и 10000 |

Пример: `/api/v1/collection-points?lat=55.75&lon=37.61&radius_m=5000&material_code=pet`.

Ответ:

```json
{
  "items": [],
  "total": 0
}
```

`total` — количество точек, подходящих под все фильтры, до пагинации. Фильтры материала, категории и региона применяются к одной и той же записи принимаемого материала. Неизвестный код даёт пустой результат, а не автоматически расширяет поиск.

С координатами результаты отсортированы по расстоянию, без них — по названию и ID. `distance_m` округляется до десятых метра. Расчёт выполняется в PostgreSQL по формуле гаверсинуса, с предварительным ограничением широты и обработкой полюсов и линии смены дат. Это расстояние по сфере, а не длина пешеходного или автомобильного маршрута. Геолокация используется для запроса и не сохраняется в таблицах приложения.

Для небольшого каталога не требуется PostGIS. При росте количества точек стоит перейти на географический тип и пространственный индекс; текущая реализация не заявляет масштабируемость до миллионов объектов.

## Карточка

`GET /api/v1/collection-points/{id}` возвращает:

- UUID, название, город и адрес;
- `latitude`, `longitude`;
- `opening_hours` — текст графика работы и `timezone` — часовой пояс IANA;
- необязательный `website` и примечания `notes`;
- `source_url` и `reviewed_at` — источник и дата проверки;
- `accepted_materials`: массив объектов с кодом и названием материала, категорией, регионом справочника и отдельными ограничениями `notes`;
- `distance_m: null`, поскольку карточка не принимает координаты пользователя.

Неактивные точки скрыты и из поиска, и из карточек. Несуществующий или неактивный UUID даёт `404`, неверный UUID и недопустимые параметры поиска — `422`.

График работы хранится как текст: фильтра «открыто сейчас» нет. Перед поездкой необходимо проверить условия у оператора, особенно ограничения по виду изделия, загрязнениям и объёму. Совпадение материала с общим справочником не гарантирует приём любого изделия из этого материала.

## Наполнение

Рабочая БД изначально не содержит пунктов: фиктивные адреса и координаты из тестов в неё не добавляются. Реальные точки нужно подготовить для выбранного города по проверенным источникам с учётом условий использования этих данных.

Доверенному оператору доступен импортёр `app.cli.import_collection_points`, принимающий путь к UTF-8 JSON-массиву. Это инструмент работы с данными, публичных ручек создания/редактирования нет.

Пример структуры записи — **вымышленные данные, не для рабочего импорта**:

```json
{
  "source_code": "operator_directory",
  "external_id": "example-123",
  "name": "Пример пункта",
  "city": "Пример города",
  "address": "Пример адреса",
  "latitude": 0,
  "longitude": 0,
  "opening_hours": "Уточнять у оператора",
  "timezone": "UTC",
  "website": null,
  "notes": "Дополнительные условия",
  "is_active": true,
  "source_url": "https://example.com/point",
  "reviewed_at": "2026-11-08",
  "reviewed_by": "Имя действительно проверившего",
  "accepted_materials": [
    {
      "material_code": "pet",
      "region_code": "general",
      "notes": "Указать фактические ограничения оператора"
    }
  ]
}
```

Импорт валидирует координаты, часовой пояс, даты, ссылки, уникальность ключей и существование пар материал/регион. Дата проверки не может быть в будущем. Наличие URL не заменяет фактическую проверку: импортёр не загружает сайт и не проверяет истинность адреса или условий.

Обновление выполняется по паре `(source_code, external_id)` и сохраняет UUID. При обновлении список принимаемых материалов заменяется целиком. Флаг `--skip-existing` сохраняет существующие точки. Отсутствующие в файле записи не удаляются; для закрытого пункта передайте `is_active: false`.

Весь импорт выполняется одной транзакцией. Невалидный материал не приводит к частичному добавлению точек. Точки связаны со справочником внешним ключом: нельзя случайно удалить используемую пару материала и региона.

## Проверки

Тесты используют только искусственные точки внутри откатываемых транзакций. Проверены радиус и порядок расстояний, фильтры, пагинация, закрытые точки, границы координат, полюса, линия смены дат, повторный импорт, сохранение ID и защита от частичной записи.

Миграция `0005_collection_points` зависит от `0004` и не требует интеграции OpenAI.
